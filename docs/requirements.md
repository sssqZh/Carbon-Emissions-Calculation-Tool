# 碳排放计算网站需求文档

## 1. 项目概述

本项目是一个本地部署的碳排放计算网站，面向个人、教学展示或小规模数据试算场景。网站后续将提供多种碳排放估算功能，例如个人碳足迹、当地电网平均碳排放因子计算、火锅碳排放等。

第一阶段暂不实现具体计算公式，重点完成：

- 前端页面框架与交互入口
- 数据库结构设计
- 计算功能的可扩展数据模型
- 本地部署与后续后端接口对接准备

## 2. 建设目标

### 2.1 第一阶段目标

- 建立网站基础信息架构，支持多个计算器模块入口。
- 设计统一的计算器页面模板，便于后续逐步添加公式和参数。
- 建立数据库表结构，用于保存用户输入、计算记录、排放因子、参考资料和公式版本。
- 支持本地运行，便于开发、演示和调试。

### 2.2 后续阶段目标

- 添加具体计算功能和公式。
- 支持用户查看历史计算记录。
- 支持管理员维护排放因子、公式说明和参考资料。
- 支持导出计算结果或生成简要报告。

## 3. 用户角色

### 3.1 普通用户

普通用户可以：

- 浏览可用的碳排放计算器。
- 填写数据并提交计算。
- 查看计算结果、排放构成和说明。
- 查看历史计算记录。

第一阶段只需要预留页面和数据结构，计算动作可先使用占位状态。

### 3.2 管理员

管理员可以：

- 管理计算器模块。
- 维护排放因子。
- 维护公式版本、适用范围和参考资料。
- 查看或导出用户计算记录。

第一阶段可只设计数据库和后台页面入口，实际管理功能可后续实现。

## 4. 功能范围

### 4.1 第一阶段包含

- 首页或仪表盘
- 计算器列表页
- 计算器详情页模板
- 计算结果展示模板
- 历史记录页
- 资料与因子库页面
- 数据库表结构
- 本地部署说明

### 4.2 第一阶段不包含

- 真实碳排放计算公式
- 用户登录注册
- 在线支付、分享、云同步
- 复杂权限系统
- 第三方 API 实时数据接入

## 5. 前端需求

### 5.1 页面结构

网站建议包含以下页面：

- `首页 / 仪表盘`
  - 展示网站名称、主要计算器入口、最近计算记录摘要。
- `计算器列表`
  - 展示所有可用或规划中的计算器。
  - 每个计算器显示名称、简介、状态、适用场景。
- `计算器详情`
  - 根据计算器类型动态展示输入表单。
  - 第一阶段可展示占位输入项和“公式待接入”状态。
- `结果页`
  - 展示总排放量、单位、分项结果、说明文字。
  - 第一阶段可展示结构，不需要真实计算结果。
- `历史记录`
  - 展示用户曾经提交过的计算记录。
  - 支持按计算器类型、时间筛选的界面预留。
- `因子库 / 参考资料`
  - 展示排放因子、来源、年份、地区、单位、备注。
  - 展示参考资料列表。
- `后台管理入口`
  - 第一阶段可只保留入口或静态页面。

### 5.2 主要前端组件

- 顶部导航栏
- 侧边栏或模块导航
- 计算器卡片
- 动态表单组件
- 数值输入组件
- 单位选择组件
- 结果摘要组件
- 分项排放条目组件
- 表格组件
- 状态标签组件
- 空状态和加载状态

### 5.3 交互要求

- 表单输入应支持基础校验，例如必填、数字范围、单位选择。
- 计算器模块应支持“草稿 / 已启用 / 维护中”状态。
- 结果展示应区分总量、分项、数据来源和公式版本。
- 页面布局应适配桌面端和移动端。
- 本地部署阶段应优先保证桌面端体验。

### 5.4 视觉风格

- 风格应偏工具型、清晰、克制，避免过度营销化。
- 主色建议使用绿色或蓝绿色，但不要让界面完全由单一色系构成。
- 表格、表单、结果卡片应强调可读性和信息层级。
- 关键数值需要醒目，但不应遮挡说明和来源信息。

## 6. 数据库需求

数据库第一阶段建议使用 SQLite，便于本地部署和迁移。后续如需要多人使用或云部署，可迁移到 PostgreSQL。

### 6.1 核心实体

- 计算器
- 计算器字段定义
- 计算记录
- 计算输入快照
- 计算结果快照
- 排放因子
- 公式版本
- 参考资料

## 7. 初始计算器规划

第一阶段建议预置以下计算器记录：

| slug | 名称 | 状态 | 说明 |
| --- | --- | --- | --- |
| personal-footprint | 个人碳足迹估算 | draft | 基于出行、饮食、居住、消费等数据估算 |
| grid-emission-factor | 当地电网平均碳排放因子计算 | draft | 基于地区电力结构或官方因子计算 |
| hotpot-emission | 火锅碳排放估算 | draft | 基于食材、能源、交通、人数等数据估算 |

## 8. 数据流设计

第一阶段建议按以下数据流预留接口：

1. 前端读取计算器列表。
2. 用户进入某个计算器详情页。
3. 前端读取该计算器的字段定义。
4. 用户填写表单。
5. 前端提交输入数据。
6. 后端根据公式版本和排放因子生成结果。
7. 后端保存计算记录。
8. 前端展示结果并允许用户回看历史记录。

在第一阶段，第 6 步可使用占位结果或暂不启用。

## 9. 本地部署需求

### 9.1 推荐技术栈

前端：

- React 或 Vue
- TypeScript
- Vite
- 表格和表单组件可使用轻量 UI 库，也可以先自建基础组件

后端与数据库：

- Node.js + SQLite，或 Python + FastAPI + SQLite
- 第一阶段如重点是前端和数据库，可先使用本地 SQLite 文件和简单 API

### 9.2 本地运行要求

- 支持一条命令启动前端开发服务器。
- 支持一条命令初始化数据库。
- 支持种子数据导入。
- 数据库文件不应提交敏感数据。

## 10. 非功能需求

- 可维护性：计算器、字段、公式、因子应尽量数据化，减少硬编码。
- 可追溯性：每次计算结果应记录输入快照、公式版本和因子来源。
- 可扩展性：后续新增计算器时不应大规模修改数据库结构。
- 可解释性：结果页应展示计算依据和参考资料。
- 本地优先：第一阶段不依赖外部服务即可运行。

## 11. 第一阶段验收标准

- 存在清晰的网站页面结构和导航。
- 至少有三个计算器入口：个人碳足迹、电网排放因子、火锅碳排放。
- 计算器详情页能够展示对应输入字段的占位表单。
- 数据库包含计算器、字段、记录、排放因子、公式版本、参考资料等核心表。
- 可以初始化数据库并写入初始计算器数据。
- 页面中能展示因子库和历史记录的基础结构。
- 项目可以在本地启动。

## 12. 暂缓决策项

以下内容等具体公式和参考资料确定后再细化：

- 每个计算器的具体输入字段。
- 排放因子的来源优先级。
- 计算单位和单位换算规则。
- 结果报告格式。
- 是否需要登录和多用户隔离。
- 是否需要从官方数据源自动更新因子。
